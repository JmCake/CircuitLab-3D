# 技术决策、边界与风险登记

## 已确定

1. **产品方向**：大学教学中的真实实验室式 3D 电路平台，兼顾自由搭建与教学实验，非单一“面包板网站”。
2. **技术主线**：React + TypeScript → Three.js + React Three Fiber → WebGL 2；电路图/求解器与渲染解耦。
3. **资产策略**：首期器材采用代码程序化建模，不依赖 Blender 模型作为主线。
4. **仿真主线**：先稳定直流线性电路与 MNA，再扩展 LED 等非线性器材与 RC 暂态。
5. **交互主线**：基于端口的显式接线，空间相交不等于电气连接。
6. **课程主线**：先完成欧姆定律完整实验，再扩展串并联与基尔霍夫实验。
7. **当前交付边界**：**已授权并完成实际开发**。仓库当前包含可运行的 Vite/React/R3F 应用、电路求解器、六组教学实验、测试与截图；不再处于 Planning Only。实际边界见 [IMPLEMENTATION_STATUS.md](IMPLEMENTATION_STATUS.md)。

## 实施阶段新增技术决策（2026-11-13）

8. **状态管理选用 Zustand**：实验状态、历史快照、自动保存和瞬时解算都在一个轻量 store 中；不引入后端。
9. **直流求解采用节点分析**：电压源使用带内部电阻的诺顿等效，避免理想电压源并联/短路导致矩阵奇异；高斯消元在小规模教学电路上更易测试与诊断。
10. **每个物理子网络独立选地**：允许学员先摆器材后接线而不崩溃；同时显式报告未接电源的浮置子网络。
11. **端口与网格解耦**：导线用完整 Port ID 记录，曲线几何只读取端口世界坐标；空间交叉不会创建电气节点。
12. **非线性 LED 使用主动集分段线性模型**：保证真实电流/电压驱动亮度，但明确不宣称完整 Shockley 精度；未来可替换为 Newton 迭代。
13. **面包板采用 42 孔教学板**：每列五孔和两条纵向电源轨实现内部连通，优先在浏览器内保证可读与可交互；标准全尺寸板列入 P6。
14. **UI 采用 DOM 侧栏，不把表单放进 3D**：三维仅承担空间操作与世界空间反馈，保证中文文本可读性、可访问性和布局一致性。
15. **不加入外部 HDR/GLB/字体资产**：环境反射由 Drei Lightformer 程序化生成，文字由 CanvasTexture 生成，避免运行时依赖外部 CDN。

## 主要风险及当前状态

**R1｜3D 模型好看但不可接线。** 已缓解：端口 ID、独立拾取体、世界坐标派生、真实浏览器拖线通过。剩余风险：复杂遮挡下的拾取仍需继续测试。

**R2｜用动画代替仿真。** 已缓解：仪表、屏幕、LED、灯泡和 RC 曲线全部读取同一 `SimulationResult`，无随机读数；单元测试使用解析电路回归。

**R3｜MNA 遇到短路、悬空、理想源冲突而失败。** 已处理有限内阻电源的短路、浮置网络和奇异矩阵路径；当前不展示 NaN/Infinity。主动恒流/截止保护仍未实现。

**R4｜LED、电容、灯泡超出基础线性直流模型。** 已明确标注为分段线性 LED、功率亮度灯泡和后向欧拉 RC；不在教学中冒充全 SPICE。

**R5｜渲染性能不足。** 共享材质、限制 DPR、单方向光阴影、2048 阴影图、静态环境贴图。硬件性能尚未验证；软件 SwiftShader 下约 5 fps，不能代表目标设备。

**R6｜过度工程化。** 未引入后端、账号或多人协作；范围集中在教学闭环与验证。

**R7｜教学正确性与外观“真实”不一致。** 实验说明中列出仪表内阻、导线/接触电阻忽略、温度与非线性假设；面包板和旋钮的教学简化在 UI 与文档中明确。

仓库可见性沿用 GitHub 现有设置；未在未授权的情况下添加开源许可证。第三方依赖保留各自许可证；没有复制第三方模型、素材或代码。

## 外部项目借鉴约束

可研究 ohmlet、LABSIM、OpenBreadboard、CircuitJS1 的交互或仿真思想，但**不得直接复制第三方项目代码/素材而忽略其许可证要求**。技术选型应通过自主原型和测试复核。
