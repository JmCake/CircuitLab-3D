# 技术决策、边界与风险登记

## 已确定

1. **产品方向**：大学教学中的真实实验室式 3D 电路平台，兼顾自由搭建与教学实验，非单一“面包板网站”。
2. **技术主线**：React + TypeScript → Three.js + React Three Fiber → WebGL 2；电路图/求解器与渲染解耦。
3. **资产策略**：首期器材采用代码程序化建模，不依赖 Blender 模型作为主线。
4. **仿真主线**：先稳定直流线性电路与 MNA，再扩展 LED 等非线性器材与 RC 暂态。
5. **交互主线**：基于端口的显式接线，空间相交不等于电气连接。
6. **课程主线**：先完成欧姆定律完整实验，再扩展串并联与基尔霍夫实验。
7. **当前交付边界**：仅提交计划、架构图和验收标准，不开始代码实现。

## 主要风险及应对

**R1｜3D 模型好看但不可接线。** 每个端口必须有稳定 ID 和位置；几何外观与连接逻辑分离；优先实现端子拾取和导线吸附。

**R2｜用动画代替仿真。** 电表、灯光只读取求解结果；用标准解析电路建立回归用例。

**R3｜MNA 遇到短路、悬空、理想源冲突而失败。** 提前做拓扑预检查，使用电源内阻/限流假设和明确错误状态；绝不显示 NaN/Infinity。

**R4｜LED、电容、灯泡等超出基础线性直流模型。** 明示近似模型；分阶段扩展数值求解，不在 MVP 宣称全面 SPICE 能力。

**R5｜渲染性能不足。** 控制材质/Draw Call、缓存几何、避免每帧重建网表；基于集成显卡设备量化性能。

**R6｜过度工程化。** 不先做账号后台、AI 助教、多人协作、大规模教务系统；按 P1 至 P4 建立闭环后再扩展。

**R7｜教学正确性与外观“真实”不一致。** 在实验说明中标注仪表内阻、元件误差、温度与非线性是否被建模；允许教师选择理想/近似实验条件。

## 外部项目借鉴约束

可研究 ohmlet、LABSIM、OpenBreadboard、CircuitJS1 的交互或仿真思想，但**不得直接复制第三方项目代码/素材而忽略其许可证要求**。技术选型应通过自主原型和测试复核。
