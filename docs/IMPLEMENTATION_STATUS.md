# 实现状态与验证记录

> 记录日期：2026-11-13  
> 版本：`v0.1.0`  
> 结论：仓库已从 Planning Only 进入可运行开发版本。P1–P5 的核心闭环已完成；P6 完成了 RC 暂态核心，硬件性能、跨浏览器和无障碍完善仍未完成。

## 1. 当前可用闭环

1. 打开页面查看完整三维实验桌和器材。
2. 从器材库拖入或点击添加器材，在桌面上移动、旋转、删除。
3. 点击接线柱拉出导线，吸附到另一个端口；导线端点随器材移动更新。
4. 打开电源、闭合开关、旋转电压旋钮或调节电阻。
5. 求解器根据端口/导线拓扑重建网表，计算节点电压与元件电流。
6. 数字屏幕、电流表/电压表读数、LED、灯泡和 RC 曲线由同一结果快照驱动。
7. 教学步骤根据真实类型、连接关系和数值给出完成/未完成状态。
8. 记录数据、导出 CSV/JSON、保存到 localStorage，刷新后恢复并重新计算。

## 4. 交互与输入仲裁

- 拖拽器材和调节控件期间自动禁用 OrbitControls，避免相机同时转动。
- 端口拾取使用独立透明命中体，端口高亮环区分起点、悬停、可连接/不可连接。
- 选中装饰的射线检测被禁用，避免选中框/标签抢走旋钮点击。
- 旋钮、摇板、电阻箱十进制旋钮和变阻器滑片均有独立指针处理与平滑动画。
- 端口最多三根导线；重复线、非法端点和超过堆叠数量都会被拒绝并提示。
- 撤销/重做采用快照历史（上限 60），所有拓扑与参数变更均记录。

## 5. 求解器与物理假设

- 端口连接通过 `Wire.fromPortId / toPortId` 建立，使用并查集合并节点；相邻或空间相交不会连接。
- 电源使用诺顿等效（理想电压源与 0.2 Ω 串联内阻），因此直接短路仍得到有限大电流并产生诊断。
- 每个独立网络单独选参考地；悬空网络会显示明确诊断，不会被悄悄赋予错误数值。
- 线性系统使用带部分主元的高斯消元；矩阵奇异、非有限解和元件非有限值都会回退为空读数并给出错误。
- LED 采用分段线性模型，主动集迭代 + 小规模状态枚举兜底；不宣称完整 Shockley 精度。
- RC 使用后向欧拉伴随模型，默认 `dt = 20 ms`；曲线采样点使用仿真时间，不依赖渲染帧率计算电学结果。
- 电流表、电压表有真实的内阻负载效应；仪表读数取自动态结果快照，不是根据空间位置估算。

### 6.2 浏览器验收

命令：`npm run test:e2e`（会按需启动 Vite，并调用系统 Chrome/Edge）

验证动作与结果：

- 默认场景渲染、WebGL 2 上下文有效。
- 3D 电压旋钮向上拖动：6.0 V → 11.5 V；器材位置未随旋钮拖动改变。
- 3D 电源摇板开关关闭/恢复：输出标志与结果状态同步。
- 从真实端口拖拽接线：新增 1 根导线，撤销/重做恢复正确。
- 载入 E01 示范：6 根导线；电流表读数约 5.999 mA；电压表约 5.998 V。
- 记录数据：U≈5.998 V，I≈5.999 mA，反算 R≈999.9 Ω；教学进度 5/5。
- 逐组载入六组实验示范并求解成功；LED 实验 `ledOn === true`。
- RC 暂态：采集约 51 个时间步，电容电压上升至约 4.93 V；停止/继续/重置控件存在。采样数量会随机器负载变化。
- 刷新后恢复 6 件器材、7 根导线、1 条测量记录；结果重新计算（暂态时间重置）。
- CSV 下载文件名 `circuitlab-rc-measurements.csv`。
- 帮助面板可开关；自由搭建模式面板可进入并返回指导实验。

### 6.3 视觉检查

使用系统 Chrome `ANGLE + SwiftShader` 在 1600×1000 视口检查了：默认全景、仪器正面/45°近景、接线状态、仪表读数、LED 点亮、小灯泡点亮、全部器材总览、RC 曲线与帮助面板。截图保存在 [`docs/media/`](media/)。

开发过程中另外通过隔离浏览器脚本检查了：电阻箱四只十进制旋钮点击、变阻器滑片水平拖动、LED/灯泡亮度由元素结果驱动。由于 3D 屏幕投影在软件渲染下速度很低，这些检查保留为视觉/人工验证，不放进必须通过的 CI 脚本。

### 6.4 构建与实际渲染统计

命令：`npm run build`，通过。Vite 输出为 Three.js/R3F vendor、应用入口、icons 与 state 分块：`three-*.js` 约 1.20 MB（gzip 338 KB）、应用入口约 206 KB（gzip 61 KB）、CSS 45 KB（gzip 9.3 KB）。生产构建不包含空壳页面。

默认场景渲染统计（SwiftShader 软件 WebGL）：

- 约 438 draw calls，44,554 triangles，366 geometries，48 textures（首帧后的信息）。
- 浏览器 `requestAnimationFrame` 约 5 fps；这是软件光栅化结果，**不能作为集成显卡性能数据**。
- RC 和全部器材加载后约 574 draw calls / 62,684 triangles。
- Chrome/Edge 使用页面 WebGL 2 渲染且无 context lost。

## 7. 明确未完成或未验证

- **硬件 GPU 性能**：当前测试环境为 SwiftShader；未在真实集成显卡笔记本上测帧率，未验证 60 fps 目标。
- **跨浏览器**：未在 Firefox/Safari 实机测试；仅 Chromium/Chrome 测试。
- **移动端/触屏**：未完成触摸手势与窄屏交互设计。
- **完整 SPICE 精度**：未实现交流、电感、完整二极管指数模型、温度/热效应、导线电阻与接触电阻。
- **电源限流保护**：用有限内部电阻和短路告警代替主动恒流/截止保护。
- **面包板规模**：42 孔教学板，不是标准 830 点面包板；端口到接线端子规则已实现。
- **电阻箱旋钮**：点击递增/回绕，不是连续拖动多位旋钮；数字参数输入是替代方式。
- **RC 墙钟同步**：暂态步长以 `setInterval` 驱动，低帧率或后台节流时仿真时间可能慢于真实时间；UI 标注“仿真时间”，曲线以仿真时间为准。
- **3D 视觉**：仪器比例为教学近似，LED/灯泡为放大教学模块；材质与几何不是工业 CAD。
- **无障碍**：有基本键盘快捷键与 focus 样式，但未完成完整屏幕阅读器与全键盘操作流。

5. 扩展实验记录图表、误差分析、导出报告，并完善无障碍与移动端。
