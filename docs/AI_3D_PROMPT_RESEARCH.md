## 二、从公开提示词提炼的 7 个必备部分

1. **角色与交付**：指定代码 3D 技术美术/工程师角色，说明输出是可运行原型还是仅规划；明确文件、仓库和阶段边界。
2. **空间与构图**：说明“从哪里看”以及物体在什么空间使用，比如大学实验台的 3/4 斜俯视构图，而不是抽象空场景。
3. **几何结构细目**：拆分壳体、面板、刻度、旋钮、金属端子、插头等；给出比例、局部坐标、枢轴、方向。
4. **外观与材质**：区分喷涂金属、塑料、橡胶、玻璃等材质，指定柔和主光/补光/接触阴影，避免材料全部相同。
5. **交互动作与状态**：为端口拾取、拖放、相机操作、旋钮状态和导线吸附给出确定输入、行为与反馈。
6. **技术硬约束与性能**：固定 React+TypeScript+Three.js/R3F 的角色；规定代码建模与域模型解耦、绘制预算及集成显卡测试，不把单 HTML 的演示约束错误搬到长期工程。
7. **可验证验收**：列出全景和特写应看到什么、接线成功后怎样表现、计算依据是什么、测试须如何实际执行；禁止“看似完成”但无法使用。

## 三、为本项目特别强化的原则

### 1. 专业仪器优先，而不是“场景越多越好”

比起扩大实验室楼层、摆满景观道具，更应该先精细完成一台可交互直流电源：显示区、可旋转旋钮、开关、接线端口、材质及局部坐标都应准确。之后复用结构规范创建电流表、电压表和开关。

### 2. 程序化生成 ≠ 简陋积木

代码建模可以是圆角盒、曲面、拉伸截面、车削零件、螺旋/管状导线、材质与 CanvasTexture 的组合。提示词必须明确细节层级和比例，不能仅让 AI “用 Three.js 创建电源”。

### 3. 3D 视觉正确 ≠ 电学正确

大多数公开 3D 提示词聚焦场景和互动。CircuitLab-3D 需要额外的 Port → Wire → Node → 求解器的数据链。灯泡、电表等状态只从电学结果产生，不能由演示动画伪造。这是项目相较普通三维作品最重要的附加约束。

### 4. 总体提示词 + 单器材提示词 + 阶段验收

超大的一次性提示词很容易牺牲零件质量。建议用 MASTER 作为长期规则；每次只针对一种器材或一个小闭环进行增量实现；随后根据视觉和交互验收迭代。不得越过 P1/P2 直接声称完整电路平台完成。

## 五、实际使用方法

- **长期开发约束**：将 [MASTER_PROJECT_PROMPT.md](../prompts/MASTER_PROJECT_PROMPT.md) 提供给编码助手，并指定当前获准阶段。
- **打磨具体模型**：结合 [PROCEDURAL_INSTRUMENT_PROMPT.md](../prompts/PROCEDURAL_INSTRUMENT_PROMPT.md) 指定器材和可操作结构。
- **开发质量对照**：依照 [ARCHITECTURE.md](ARCHITECTURE.md)、[ROADMAP.md](ROADMAP.md) 与 [ACCEPTANCE.md](ACCEPTANCE.md) 判断完成度。
- **尚未允许开发时**：这些提示词只是文档，不能视为启动实施的指令。

### 观察与结论

- **能够公开取得的提示词往往把需求拆成清晰的功能动作**，例如“输入手势 → 对应粒子缩放/旋转 → 实时响应”，而非只写“做一个很酷的 3D 网站”。
- **展示型 3D 作品不等于可操作实验平台**：需要把“视觉对象”补成“器材层级 + 端口身份 + 电学连接 + 数值反馈”。
- **分阶段实现，循环自检**：先实现基本鼠标与端口交互，再提高仪器建模精度和材质；真正的电路仿真在独立模块验证。
- **不要求所有复杂物体同一轮生成**：对直流电源、电压表、电流表、开关等建立可复用器材提示词；先做单仪器特写和端口拾取，再组合成完整工作台。
- **避免未经证实的“爆款万能词”**：没有获取全文的内容应标注为创作方向与案例，而不是复述不存在的原文。

- 设备提示词 `prompts/PROCEDURAL_INSTRUMENT_PROMPT.md`：按“零件结构 → 材质/相机 → 可操作输入 → 数据反馈 → 可验证标准”逐一实现。
